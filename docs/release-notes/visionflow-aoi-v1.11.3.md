# VisionFlow AOI v1.11.3

這是 v1.11.2 的 Windows x64 修正版，包含完整 `VisionFlow AOI` PyInstaller 資料夾與 CUDA `sm_86` DLL，針對相機機台回報的 Sensor 取像與光源不亮問題。

## 光源

- 工程模式可以直接輸入各通道 0–255 亮度，按「開燈」會使用畫面上的數值；亮度全為 0 時會提醒。
- 新增「逐一試亮」：依序以目前設定（通常是原程式匯入的指令）與 CCS、OPT、SA、Modbus 各常用鮑率開燈（亮度取面板值，全為 0 時用 200）。每組由你看燈有沒有亮：按「有亮」就保存這一組並保持開燈，按「沒亮，下一個」會先關掉再試下一組；全部沒亮回報 `E-2109`，按「停止」不變更設定。控制器只回 `$` 之類的單一位元組也不會中斷。
- 光源狀態會分開顯示「指令已送出」與「控制器已回覆」，不會再宣稱燈已亮；單獨一個 `$` 不再被判定為 OPT 協定。

## Sensor 軟體觸發取像

- Sensor 觸發時先確認米輪與 Compare，再開始取像；上一張還沒完成時新的觸發會略過、不補拍，並顯示米輪已走的格數。
- 修正影像落在 Sapera trash buffer 時相機一直停在「擷取中」，導致之後每個 Sensor 都被略過的問題。
- 上一張未完成又來下一個 Sensor 時，一次性說明原因：
  - `E-6106`：兩次 Sensor 之間米輪走的格數少於「Length × 每行格數」，影像比產品間距長；訊息會建議 Length 上限。
  - `E-6107`：米輪已走夠但影像仍未完成，擷取卡線觸發不足；請檢查 CMP_OUT→擷取卡接線與 CCF。

## 其他

- 設備自檢逐項標示已確認／未確認的層級，並提供不連線的快速狀態檢查；自檢與光源偵測不會互相干擾。
- 從原機台程式匯入套用後，會比對儲存值與相機讀回值。
- 新錯誤碼已加入 `docs/device-error-codes.md`。

## 驗證與限制

- 完整自動測試、語法編譯、CUDA 靜態預檢及 GUI 離屏啟動通過；逐一試亮、trash 修正與間距判讀以模擬裝置測試。
- 光源實際亮燈與連續產品的完整取像仍須在相機機台確認。
- CUDA source、C ABI 與檢測流程未改動；CPU fallback 與 Recipe 格式維持 v1.11.2 語意。

完整解壓縮 ZIP 後執行 `VisionFlow AOI.exe`，請勿只複製 EXE。
