## 2026-08-13（星期四）

- 依新規格簡化舊 Detector 202：前處理改為 Gray → 一般二值化 → 中心／四邊屏蔽 → LIST contours，固定以 2% epsilon 近似輪廓，只接受面積 5～100 且剛好 4 個頂點的四邊形，不再限制凹凸。
- 舊 Adaptive Mean、Morphology、contour mode、頂點數與凸性欄位仍可由舊 Recipe 載入，但已從 Designer 隱藏且不再影響判定；該提交記錄 15 項專屬測試與完整 229 tests 通過。
- 新增 Detector 202-1 自動 CNR 檢測，依 AcceptanceChecker 參考語意實作尺度相關 Gaussian 背景、residual、MAD robust sigma、自動異常門檻、3×3 Open、8-connectivity components、局部背景 ring 與 CNR 排序。
- Auto CNR 沿用中心／四邊屏蔽，排除像素不產生候選且不納入背景統計；候選依 CNR 降冪輸出，抓到即判定 NG。該提交記錄 10 項專屬測試與完整 239 tests 通過。

- 更新 README 的正式 ID／舊 ID 對照、相容策略、Detector 專案結構、900 架構名稱、完整 compileall 範圍與 YOLOX ONNX Runtime CPU／CUDA FP32 fallback 現況。

- 補正首次參數 audit 僅覆蓋既有 schema、未涵蓋硬編碼行為常數的缺口；進一步將 `202-CS-SN-1` Auto CNR 與 `203-AS-SN-1` 的光學／演算法常數納入 Recipe schema，並將稽核契約改為必須檢查所有 behavior-affecting constants 與 formulas。
- 將傳統 CV contour 調參程式整理為獨立 OOP 套件，移除原本最長邊 1400 的 OpenCV 運算縮圖。Preview 與 Save 共用原圖及同一處理引擎，fit-to-window 只改顯示 transform；Windows OpenGL 4.6 可用，無 context 時安全回退 Qt raster。

## 版本差異與風險

- Detector `203-AS-AP-1` 是新增時的名稱，週期末正式 ID 已改為 `203-AS-SN-1`；舊名稱由 RecipeManager 正規化，不應再寫入新 Recipe。
- 舊 Detector `202` 已不再是正式可註冊 Detector，舊 Recipe 若仍直接使用 `202` 會明確回報未註冊；其程式只作為 `202-CS-SN-1` 的內部屏蔽共用基底。
- Auto CNR 的 30% 光衰容忍度是合成模型下的暫定設計值，不是量產保證；仍需使用真實相機、曝光條件、材質、良品／不良品及可追溯 acceptance set 驗證。
- Traditional CV Tuning Tool v1.0.0 為 CPU／OpenCV 工具，OpenGL 只加速 Qt 顯示；程式未簽章，部署時可能出現 Windows SmartScreen／未知發行者提示。
- 本週僅確認本地 tag 與版本契約存在，未將 GitHub Release 發布狀態列為已驗證事項。
