# AOI CV Based 流水帳報告

日期：2026-07-30（星期四）至 2026-08-05（星期三）

本週主要工作集中在 RTX 3090 CUDA backend 修復與實機驗收、YOLOX 模型選擇流程、Windows 發布與工具打包，以及 AOI 核心與 GUI 的 OOP 責任邊界重構。期間共完成 12 筆提交，異動 69 個檔案，新增 4,693 行、刪除 1,844 行；完整測試套件由 190 項增加至 207 項。週期末版本為 VisionFlow AOI v1.2.0，並另外發布 VisionFlow Utility Tools v1.0.0。

## 2026-07-30（星期四）

- 調整 YOLOX Recipe Designer 的模型選擇流程。最初由模型資料夾載入 `registry.yaml`，後續改為直接選擇 `.onnx` 檔案，再用同資料夾內的 registry 驗證 model ID 與 SHA-256。
- 新流程支援同一份 registry 管理多個 ONNX 模型，Recipe 仍只保存穩定的 `model_id`；目前沒有 PyTorch 推論後端，因此 `.pt` 與 `.pth` 會明確拒絕。
- 修正 Windows 下拉選單黑底黑字問題，統一設定 `QComboBox` 本體、停用狀態、popup 與選取項目的前景／背景色，GPU Mode 與共用參數下拉選單同步套用。
- 將 `aoi-verify-push`、`aoi-detector-development`、`aoi-cuda-validate`、`aoi-release` 四個 AOI 專用 Codex skills 複製到 repository，補上可攜式安裝程式與新機安裝說明。
- 在 RTX 3090 初次驗證 GitHub Actions CUDA artifact 時，35 個 exports、dependencies、native ABI／plan／ROI batch smoke 及 1,000 次 persistent-plan reuse 通過，但正式 validator 的 72 個數值案例仍有 10 項失敗，另有 1 項 repository preflight import error。
- 針對上述 blocker，將 artifact／repository 工具改為 repo-local manifest 與受控發布，修正 BGR 轉灰階係數與 Gaussian 3～127 的 OpenCV bit-exact 行為。
- 使用 CUDA 13.3、MSVC 19.51 與 `sm_86` 重新編譯 DLL、LIB 與 native test EXE；在 RTX 3090 上連續三次執行完整 validator 均為零失敗。
- 完成 correctness、4K benchmark、crossover、morphology profile、10／100／1,000 次 stress，以及五份 production Recipe 合成影像的 CPU／GPU pipeline 等價驗證。1,000 次 checkpoint 的 allocation count 固定為 25、reserved bytes 固定為 222,435,236，free VRAM 未下降。

## 2026-07-31（星期五）

- 為 Pattern 固定網格切圖工具新增獨立 PyInstaller one-file spec 與建置腳本，成品不需安裝 Python 或 CUDA DLL 即可使用。
- 完成 Pattern 工具無參數 GUI 啟動、CLI 合成影像 4-tile 與 CSV manifest smoke。
- 發布 VisionFlow AOI v1.2.0 CUDA-enabled Windows x64。發行包使用同一 release commit，以 CUDA 13.3／`sm_86` 重編並在 RTX 3090 驗證的 `visionflow_cuda.dll`。
- 調整 CUDA 二進位檔管理方式：Git 只追蹤 CUDA source、header 與建置腳本，DLL／LIB／EXP／native test EXE 不納入版本控制，正式成品只放入版本化 ZIP 與 GitHub Release。
- 修正 Windows CI 的 UTF-8、resolved path 與 YOLOX model directory portability 問題，並補齊 GUI launcher 與 standalone exporters 的 compileall 範圍。
- 收緊 Windows、weekly 與 RTX workflows 的權限與環境：改用 `contents: read`、lock-file cache、乾淨 venv、精確 repository guard，並替 RTX heartbeat 增加 5 分鐘 timeout。
- 修正 weekly packaging 無法從 windowed PyInstaller EXE 可靠取得 `$LASTEXITCODE` 的問題，改用 `Start-Process -Wait -PassThru` 取得真實 smoke exit code。
- 依 GitHub Node 20 deprecation 警告，更新 checkout、setup-python、upload-artifact、cache 與 github-script 至官方 Node 24 版本。
- 將 NG Tile 面積分類、Pattern 固定網格切圖、矩陣 CSV 彙總與散點圖匯出四個小工具，統一打包成可雙擊 GUI／命令列使用的 one-file EXE。
- 四支工具都加入版本資訊與非互動 `--smoke-test`，並完成實際資料驗證：NG 複製 1 張、矩陣彙總 1 列、散點圖 1 張、Pattern 切圖 4 張。
- 發布 VisionFlow Utility Tools v1.0.0 工具合集；同期完整測試套件增加至 200 項，主程式 PyInstaller build 與 packaged smoke exit 0。

- 新增 `DetectorManager.ai_performance_stats()` 與 detector 共用的 public `device_name` contract，pipeline 不再跨模組讀取 `_ai_manager()` 或 YOLOX `_ai_execution` 私有狀態。

## 尚待完成

- 目前 GitHub repository 尚未註冊符合 labels 的 RTX self-hosted runner，因此 RTX workflow runtime 驗收仍無法在 Actions 上自動執行；本週 CUDA 結論來自已記錄的 RTX 3090 本機實測。
- 五份 production Recipe 仍需各補一張固定且可追溯的 PASS／NG 真實案例，共 10 個案例，才能完成正式量產資料驗收。
- YOLOX 仍缺 production ONNX 權重、class mapping 與人工標註 acceptance set；目前 tiny fixture 只能證明軟體契約，不能代表真實缺陷辨識準確率。
- 仍需使用固定 production 資料集量測 CPU／GPU cold／warm median、P95、吞吐、VRAM 與長時間穩定性，再決定正式環境的 backend 與效能門檻。
- GPU error／OOM recovery、不同 shape／channel 的 persistent buffer 行為、ROI batch 大小與 production crossover policy 仍需補齊實機驗證。
- Utility Tools EXE 尚未簽章，對外部署時仍需說明 Windows SmartScreen／信任提示。
