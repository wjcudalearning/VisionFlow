## 本週重點整理

- CCD 從規劃推進到 GUI、Recipe、Sapera／米輪 binding、觸發自動化、frame 直連檢測、離線打包與現場診斷；多次 release 把機台回報轉成明確錯誤碼與讀回值，並保留缺硬體時的安全不可用模式。
- GPU 路徑同時處理 correctness、顯存與觀測成本：working-set admission、timing opt-in、等價契約、scratch trim、Adaptive Mean 低顯存，以及 resident Pattern Match；效能不佳的 Contour 路徑沒有在 auto 模式啟用。
- Traditional CV 調參工具已能匯出 CPU/OpenCV reference Detector bundle，帶入無繪圖執行路徑、座標／邊界警告、golden regression 與 packaged smoke，並正式發布 v1.1.0。
- v1.8.1 為目前對外使用基準；它修正 v1.8.0 的 Pattern Match VRAM 高估與建置 PATH 汙染，GitHub Release 為 Latest。

## 版本差異與風險

- v1.6.3 至 v1.7.8 多為相機現場診斷的快速過渡版本；相機部署應以 v1.8.1 為基準，並保留診斷短碼、讀回值、正確 CCF 與機台 Sapera／driver 版本證據。
- v1.8.1 的 resident Pattern Match 目前只對較小模板有正式可用證據；release notes 明示 512×512 以上（含 256×2000、2000×256）native 會回報不支援，auto 回 CPU、strict cuda 明確失敗。Contour GPU 對長輪廓仍慢，且 VRAM admission 仍偏保守。
- RTX 3090、CUDA 13.3、sm_86 與合成影像的效能／等價結果不可擴張為真實產線 acceptance；Todo 中標示【實物】的 production recipes、真實 PASS／NG、相機外部觸發與完整現場流程仍未完成。
- 發行包未簽章，Windows 可能顯示 SmartScreen／未知發行者；CPU-only 仍是完整支援且為 correctness reference，舊／缺少 optional CUDA exports 時必須依 cpu／auto／cuda 契約處理。
